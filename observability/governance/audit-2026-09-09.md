### User-facing copy is not medical

**Declared rule.** User-facing copy in TUI chrome and help strings,
`README.md`, `ONBOARDING.md`, and `idea.md` product claims must not
present the application as diagnosing, treating, prescribing, or giving
medical advice. Paraphrase counts. Internal docs (`HARNESS.md`,
`CLAUDE.md`, `AGENTS.md`) and non-product comments are out of scope.

**Governance requirement.** The application must remain a tracking and
analysis tool rather than presenting itself as a medical diagnosis or
treatment system.

**Operational meaning (as written).** Those four surfaces must not claim
diagnosis, treatment, prescription, or medical advice. Feature behaviour
(trend, meal planning) and a visible disclaimer are out of scope.

**Verification / evidence / failure action (as written).**
harness-enforcer reviews the listed surfaces on the PR, including
paraphrase. Evidence is harness-enforcer PR output. Failure action is
block merge.

**Enforcement / tool / scope.** agent / harness-enforcer / pr.

**Frame check (as written).** Copy-only is an explicit scope limit —
this constraint does not ban clinical-adjacent features or require a
disclaimer. Engineering, compliance, and AI frames agree on user-facing
copy only. The same block notes that agent PR constraints are not
dispatched in CI today (`harness.yml` does not run harness-enforcer).

## 4. Debt Cycle Analysis

Looked for governance → intent → cognitive → technical → governance.

**No cycle detected.** One new constraint, first audit, no prior
governance-debt inventory to compound.

A seed exists, not a cycle:

1. **Governance** declares block merge.
2. **Intent** (idea.md) is already a tracking tool; no intent drift.
3. **Cognitive** risk: agents and humans may believe medical-sounding
   copy cannot merge because a constraint says "block merge".
   ONBOARDING's "At PR time" list currently omits this constraint, which
   slightly *reduces* that false confidence for this row, but it still
   describes agent-reviewed naming/layout/errors/docs as PR-enforced
   while CI does not run harness-enforcer.
4. **Technical**: no implementation was driven by a wrong reading of
   "not medical" (no disclaimer screen, no feature deletion).
5. **Governance** has not yet spawned a second constraint from the
   mismatch.

If the next governance constraint is written with "block merge" and
harness-enforcer without a workflow step, this seed becomes a cycle.
The recommendation in §5 is to close the seed now.

## 5. Prioritised Recommendations

1. **Close the gate or retarget the failure action (debt score 4).**
   Either add a required PR step that runs harness-enforcer against
   `HARNESS.md` agent constraints, or change this constraint's failure
   action and evidence to whatever actually happens today (human /
   agent review comment, no merge block). Until one of those is true,
   do not call the row Falsifiable. Prefer wiring the enforcer if the
   compliance frame still wants block merge.

2. **Do not widen the rule.** Do not add a required disclaimer, do not
   ban trend or meal planning, do not pull `HARNESS.md` / `CLAUDE.md` /
   `AGENTS.md` into scope. The Frame check already resolved that split.
   Widening would be Stage-3 drift in the other direction.

3. **Keep a paraphrase-capable reviewer even if a deterministic
   tripwire is added.** A `gofmt`-style grep for `diagnos|prescri|medical
   advice` on the four surfaces can fail closed on sloppy copy; it
   cannot see paraphrase. The constraint correctly names an agent tool
   for that. A script is a complement, not a replacement.

4. **Regenerate ONBOARDING after the constraint set changes** so "What's
   Enforced" either lists this rule *and* tells the truth about agent
   dispatch, or stops implying that every PR-scope agent constraint is
   a green check. That is documentation hygiene, not a new governance
   constraint.

5. **Next audit (quarterly, target 90 days).** Re-score this row after
   recommendation 1. If CI still does not run harness-enforcer and the
   failure action is still "block merge", keep Stage 3 and raise drift
   risk. If the gate exists and copy-only meaning is unchanged, Stage 1
   and Aligned are available. Drift velocity stays `stable` until a
   second audit can compare stages.

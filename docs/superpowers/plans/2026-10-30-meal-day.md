## Algorithm notes

-   `food` is `id`, `name` unique, and `calories`, `protein`,
    `carbohydrate`, `fat`, all per 100 g. `meal_line` is
    `id`, `day` as `YYYY-MM-DD`, `food_id`, and `grams`. No
    copied nutrients, no allowance, no density, no recipe
    table. SQLite's default collation stays, so the unique
    name is case-sensitive. Do not use `COLLATE NOCASE`.
    There is no unique pair of day and food: two lines may
    share a food. Deleting a line does not delete the food.
    This slice has no delete-food operation.
-   A line contributes `nutrient * grams / 100`. Totals sum
    that in float64. The idle screen prints totals and gram
    weights with `fmt` one decimal, the same call the weight
    column uses. `1.25` prints `1.2`. `0.25` prints `0.2`.
    If that text is `-0.0`, print `0.0`. The grams editor
    and the nutrient editor show `strconv.FormatFloat`
    with `'f'` and precision `-1`, so Enter on an
    unchanged field stores the same number. A blank
    nutrient on `e` refuses the whole edit and writes
    nothing. Totals use the stored number, not the idle
    gram text.
-   Trim the name with `strings.TrimSpace` before match and
    before store. Do not collapse a middle space. Enter
    on the add form saves only when the fields match
    that trimmed name. A name changed since the last Tab
    is `name: press tab` and writes nothing. After Tab,
    a match reuses that food and does not write its four
    numbers. A miss inserts the food and the line in one
    save. A refused save inserts neither.
-   A gram value, after trim, is an optional `+`, then
    digits with at most one dot, or a dot and digits. Then
    `ParseFloat`. Refuse `<= 0`. Refuse anything else,
    including `1e2`, `1/4`, and a unit token. `100`,
    `+100`, and `.5` are valid. A nutrient, on add and
    on `e`, uses that grammar, and zero is allowed.
    Empty after trim is missing, not zero. Refuse
    `1e2`, `inf`, `NaN`, `1/4`, a unit token, and a
    negative. `0`, `+10`, and `1.25` are valid.
-   `meal.Open` stats the path. If the file is missing, it
    returns an error and does not create it. `dailylog.Open`
    remains the creator, so mode `0600` stays that file.
    Do not `os.Create` the database. On an existing file,
    `CREATE TABLE IF NOT EXISTS` for `food` and `meal_line`
    only. Do not `ALTER` `daily_log`. Turn foreign keys on
    for this connection. A second connection beside the
    daily-log store is fine. Do not hold a transaction
    across a key.
-   Order is insertion order (`id` ascending). A new line
    is selected. Removing a line selects the following
    line, or the new last line, or nothing. Up and down
    stop at the ends. `j` and `k` are not those keys.
    Changing the date selects the first line, or nothing
    when the date is empty. While a form is open, `[` and
    `]` are not date keys. Idle `[` and `]` use
    `AddDate(0, 0, ±1)` on the civil date, not a 24-hour
    step. Today is `localToday`. Tests freeze it with
    `freezeToday`. The spec does not name that helper.
-   While the screen is meals, `savedMsg` does not set
    `a.screen` and does not change the list row Esc
    will restore. It still returns `a.load`. `loadedMsg`
    still replaces `a.logs` and still clears `a.err`.
    It does not clear the meal screen's own error, and
    it does not move that saved list row.
    `loadErrMsg` on the meal screen does not set
    `a.err`. A form parse error stays a form error. A
    month error stays a month error. The list after
    Esc is the log, not the failed-load view.
-   `UseMeals` on a nil store: `f` stays on the list and
    does not panic. `cmd/hdtools` always sets it on the
    TUI path. If `meal.Open` fails, close the daily-log
    store and return the wrapped error. Do not start the
    program. `-log-pdf` and `-chart-pdf` return before
    `meal.Open`.
-   Help text is the four strings in Decision 20. Assert
    them with `visible`. List `[` and `]` stay absent from
    `updateList`. Month `f` stays on the single-rune edit
    path. Workout still skips that path. Chart `f` stays
    unmatched.
-   `display_unit` is not read on this screen. Body weight
    on the list still converts.
